# AI WorkPilot PRD

## 1. 프로젝트 개요

- 프로젝트명: AI WorkPilot
- 유형: Human-in-the-loop AI Agent 데모
- GitHub: https://github.com/junwoo1206112/AI-WorkPilot
- 데모: https://ai-workpilot-safe-agent.kimjunwoo1206112.chatgpt.site

AI WorkPilot은 한국어 업무 요청을 `계획 → 승인 → 실행 → 회고` 흐름으로 전환하는 AI Agent 프로젝트입니다. AI가 만든 계획을 바로 실행하지 않고, 사용자의 승인 이후에만 실행되도록 설계했습니다.

## 2. 문제 정의

메일 발송이나 일정 등록처럼 결과가 남는 업무를 AI가 바로 수행하면, 사용자가 실행 내용을 확인하지 못하거나 잘못된 요청이 실행될 수 있습니다. 또한 실행이 실패했을 때 어떤 단계에서 문제가 발생했는지 확인하기 어렵습니다.

## 3. 목표

1. 한국어 업무 요청을 단계별 작업 계획으로 정리한다.
2. 위험도가 있는 작업은 사용자 승인 전 실행되지 않게 한다.
3. 실행 결과와 실패 이력을 남겨 사용자가 흐름을 확인할 수 있게 한다.
4. 실패한 단계는 멱등 방식으로 재시도할 수 있게 한다.

## 4. 주요 사용자 흐름

1. 사용자가 한국어로 업무 요청을 입력한다.
2. Planner가 요청을 작업 단계와 위험도 정보가 포함된 계획으로 변환한다.
3. 사용자가 작업 계획과 승인 사유를 확인한다.
4. 승인된 계획만 Executor가 실행한다.
5. 실행 상태와 이벤트 이력이 타임라인으로 저장된다.
6. 실패가 발생하면 실패 단계와 원인을 확인하고 재시도한다.

## 5. 주요 기능

| 기능 | 내용 |
| --- | --- |
| 작업 계획 생성 | 업무 요청을 실행 단계로 구성 |
| 승인 정책 | 승인 전 실행을 서버에서 차단 |
| 상태 관리 | `awaiting_approval → approved → running → completed / failed / cancelled` 상태 관리 |
| 실행 이력 | 실행·단계·도구 상태를 구조화된 타임라인으로 저장 |
| 실패 처리 | timeout 시뮬레이션과 실패 단계의 멱등 재시도 |
| 민감정보 제한 | 비밀번호, 주민번호, 이메일, 전화번호 형태의 입력을 계획 저장에서 제한 |

## 6. 기술 및 구조

- TypeScript
- Planner → Policy → Executor → History 어댑터 구조
- D1 기반 실행·이벤트 이력 저장
- 반응형 웹 UI 및 키보드 포커스 지원

현재 데모는 외부 API 키 없이 재현 가능한 결정론적 시뮬레이션입니다. 실제 메일·캘린더 API를 호출하지 않으며, `calendar.mock`, `mail.mock`을 통해 업무 실행 흐름을 검증합니다.

## 7. 검증

- 승인되지 않은 실행 요청은 서버에서 차단한다.
- 실행 상태와 이력은 D1에 저장한다.
- 의도적인 timeout 실패 후 실패 단계만 재시도할 수 있다.
- 테스트와 빌드 명령을 통해 프로젝트 동작을 검증한다.

## 8. 한계 및 향후 개선

- 실제 외부 업무 API 연동과 실제 사용자 인증은 구현 범위에 포함하지 않았습니다.
- LLM 모델을 직접 학습하거나 파인튜닝하지 않았습니다.
- 실서비스 전환 시 인증 세션, 토큰 관리, rate limit, 데이터 삭제 정책, API별 secret 관리가 필요합니다.

## 9. 지원 직무와의 연결

AI Agent 기능을 서비스에 적용할 때 필요한 작업 계획, 사용자 승인, 실행 이력, 실패 처리 흐름을 구현해 보았습니다. 에이아이태권도의 AI Agent·업무 자동화 기능 개발 업무에서 현장 요구사항을 이해하고, 사용자 확인이 필요한 지점을 구분하는 개발자로 성장하고 싶습니다.
